# Contributing to Drova

Thank you for considering contributing to Drova.

Whether you're fixing a bug, improving the UI, writing documentation or implementing a new feature, every contribution is appreciated.

## Before you start

- Search existing issues before opening a new one.
- If you plan to work on a large feature, open an issue first to discuss the approach.
- Keep pull requests focused on a single change whenever possible.

## Development workflow

1. Fork the repository.
2. Create a new branch from `beta`.
3. Make your changes.
4. Test your changes locally.
5. Open a pull request targeting the `beta` branch.

Example:

```bash
git checkout beta
git pull

git checkout -b feature/my-feature
```

## Coding guidelines

- Write clean and readable code.
- Follow the existing project structure and style.
- Avoid unnecessary dependencies.
- Keep commits small and meaningful.
- Use descriptive commit messages.

## Pull requests

Please make sure that:

- The project still runs correctly.
- Your changes are limited to the purpose of the pull request.
- You have updated documentation when necessary.
- Your pull request includes a clear description of what changed and why.

## Issues

Bug reports and feature requests are welcome.

At the moment, the project does not use "good first issue" labels. Feel free to work on any open issue that interests you, or open a discussion before starting if you are unsure.

## Code of conduct

Be respectful, constructive and open to feedback. The goal is to build a useful project together.

Thanks for helping improve Drova.
